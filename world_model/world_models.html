1 · What is a world model?

A world model learns how an environment changes in response to an action: p(next state | past states, action). Once trained, you can run it: send it actions, and it produces the next frames as if a real game engine, simulator or computer were running. A neural computer is the same idea applied to a user interface: the network takes the place of the OS and renders every pixel after every click.

How is it different from video diffusion / generative models?

Image / video generatorWorld model
ConditioningText prompt or a first frame, given onceAn action at every step (keys, mouse, joystick)
GenerationWhole clip at once (bidirectional attention across time)Autoregressive, one frame at a time, causal (it can't see the future)
InteractivityWatch itPlay it in a closed loop, in real time
What it must learnPlausible appearance and motionCause and effect: what this action does, plus persistent state
Main failureArtifacts, morphingDrift: small errors build up over a long rollout, and objects get forgotten when they're off-screen
Used forContentAgent training ("dreaming"), planning, simulators, neural game engines
In one line: a video model answers "what would a clip of X look like?", while a world model answers "if I press LEFT now, what happens next?" Many recent world models are video diffusion models made causal and conditioned on actions, so the architectures overlap. What differs is the contract.

2 · Training and inference contracts

Training (teacher forcing)

Data: trajectories (x₁,a₁, x₂,a₂, …, x_T) recorded from our own environment by a scripted or random agent (plus some human play for "interesting" coverage).

Stage A, tokenizer: input x_t (e.g. 64×64 or 128×128 RGB) → z_t (e.g. 8×8 or 16×16 grid of codebook IDs, codebook size 512). Loss: reconstruction + perceptual + commitment.

Stage B, dynamics: input = the ground-truth past z_{t-k..t} + actions a_{t-k..t} → predict z_{t+1}. Loss: cross-entropy over tokens (transformer) or denoising MSE (diffusion).

Anti-drift tricks: corrupt the context with noise or token dropout; scheduled sampling (sometimes feed the model its own predictions); a longer context window.

Inference (closed loop)

Start: a few real frames (or one), encoded to z.

Each tick: read the user's action a_t → dynamics predicts ẑ_{t+1} (sample tokens / run N denoising steps) → decode to pixels → display → append the prediction to the context → repeat.

No access to the real environment, game code or state. Only pixels and actions.

Target: ≥10 fps on the M2 Max at 64–128 px; sliding context window of k = 8–32 frames.

Evaluation: per-step PSNR/SSIM vs the real env with the same action sequence; rollout length before divergence; task probes (does the calculator show the right sum?).

1 · Neural calculator ★

●● easy-medium3–4 days1–3 GPU-h

Click buttons; the network draws the display. No arithmetic code at inference. Shot: it's right on simple sums, then confidently wrong on 3-digit ones.

64×64 · VQ 8×8 · ~20M param transformer

2 · Dreamed desktop ★

●●●●● insane8–12 days8–15 GPU-h

A toy OS with icons, draggable windows, close buttons. Mouse in, screen out. Shot: drag a window off-screen and it comes back as something else.

128×128 · cursor as explicit input · diffusion or VQ+transformer

3 · Neural terminal

●●●● hard6–9 days5–10 GPU-h

A toy shell with 5 made-up files; every pixel is generated. Shot: typing a command it never saw → invented files.

keystroke actions · text rendering is the hard part

4 · Neural paint + undo

●●● medium-hard4–6 days3–6 GPU-h

Brush, 3 colours, undo. Undo forces the model to remember the canvas from before. A natural way to explain why context length matters.

compare k=4 vs k=32 context

5 · Tilting marble table

●● easy-medium3–5 days2–4 GPU-h

Tilt the board; the ball rolls, bounces, falls into holes. Momentum needs several frames of history: 1-frame model fails, 8-frame model works.

best "physics" story; safest backup

6 · Lamp & shadows

●●● medium-hard4–6 days3–6 GPU-h

Carry a lamp around a room; walls cast shadows. Did it learn something like ray casting just from watching?

great visuals, soft gradients are VQ-friendly

7 · Gravity-flip rooms

●● easy-medium3–5 days2–4 GPU-h

One button flips gravity. The model has to learn a hidden rule switch from a single action.

clean probe: does the flip persist?

8 · Forgetful maze

●●●● hard5–8 days4–8 GPU-h

Walk away, turn around, come back: the corridor has rearranged. Shows honestly why world models struggle to stay consistent.

first-person or partial view needed

9 · Top-down tennis

●● easy-medium3–5 days2–4 GPU-h

Move the paddle, hit the ball. A callback to the tennis tracking project, so the series connects.

small ball = good tokenizer stress test

10 · Falling-sand sandbox

●●● medium-hard4–6 days3–6 GPU-h

Pour sand, water, walls and fire onto a pixel canvas. The real engine is a cellular automaton with simple local rules. Does the network learn the rules, or just the look? Shot: put fire next to water, a combination it never saw in training.

pixel-perfect rules = easy to measure error

11 · Neural aquarium

●●● medium-hard4–6 days3–6 GPU-h

Fish with their own random behaviour; you drop food or tap the glass. Unlike a calculator, there is no single right next frame, so this shows why a sampling model (tokens or diffusion) is needed instead of a model that predicts the average and blurs. Shot: deterministic model vs sampling model side by side.

best demo of stochasticity / "mean blur"

12 · Neural step-sequencer

●●● medium-hard5–7 days3–6 GPU-h

A drum-machine grid with a looping playhead; you toggle cells. The model has to keep time and remember the pattern. Stretch goal: play sound from whichever cells the predicted frame lights up, so you hear the dream drift out of rhythm. It also fits your music interest.

periodic state · audible failure mode

Recommendation: open with the neural calculator (cheap, checkable, funny failures) and finish with the dreamed desktop ("I deleted the computer and replaced it with a neural network"). Backup if the desktop drifts too much: the tilting marble table.
