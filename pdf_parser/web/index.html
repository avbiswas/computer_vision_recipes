PDF layout parser

A small detector finds the parts of a PDF page: titles, text, tables, pictures and more. Then a short program reads the page text in the correct order and writes markdown.

Model: D-FINE nano, 3.7M parameters, 8 MB · Data: DocLayNet · Runs in your browser

Open a PDF or use the sample. The model downloads once (8 MB). The PDF stays on your computer.

How it works


A PDF stores characters and their positions, but not the structure of the page. It does not tell you which line is a heading, where a table starts, or which column to read first. This project adds that structure and writes the page as markdown.





The pipeline


    
  
  1. pdf.js draws the page as an image and reads the PDF text layer (characters and their positions).
    2. 
  
  2. The detector finds the regions of the page: 11 classes such as Title, Text, Table, Picture and Caption.
    3. 
  
  3. Rules remove duplicate boxes (two boxes on the same region: keep the higher score).
    4. 
  
  4. Rules sort the regions into reading order: full-width blocks cut the page into bands, then the left column comes before the right column.
    5. 
  
  5. Each piece of text goes to the box that contains it. The class sets the markdown: Title → #, Section-header → ##, List-item → -.
    6. 



Only step 2 uses a neural network. The text comes from the PDF, so normal PDFs need no OCR.


The detector: D-FINE nano







    
  
  1. Backbone. A small CNN (HGNetv2) turns the 1024 × 1024 page into feature maps at two scales: 64 × 64 and 32 × 32.
    2. 
  
  2. Hybrid encoder. Self-attention runs only on the small 32 × 32 map, where it is cheap. A CNN then mixes the two scales.
    3. 
  
  3. Query selection. The 300 positions with the best scores become the first boxes and the 300 queries. This is a DETR-style detector: no anchor boxes and no non-maximum suppression.
    4. 
  
  4. Decoder (3 layers). The queries look at each other (self-attention), then each query samples 6 points per scale from the feature maps (deformable cross-attention).
    5. 
  
  5. Heads. Each query outputs a class (11 classes) and a box. The page keeps the boxes above the confidence slider.
    6. 








    
  
  1. Each box edge is a probability over 32 small offsets, not one number.
    2. 
  
  2. Each decoder layer makes the distribution sharper, so the edges become accurate layer by layer. This is important for thin regions such as page footers.
    3. 
  
  3. During training, the last layer teaches the earlier layers its distributions (self-distillation, GO-LSD). This costs nothing at run time.
    4. 



We fine-tuned the COCO weights on DocLayNet (about 80,000 labelled pages). In fp16 the model is 8 MB, and onnxruntime-web runs it on WebGPU (about 40–130 ms per page) or on the CPU.
